情境是：

> **一籃子股票在回測開始時就已經確定存在，只是每支股票「上市／可取得歷史資料的時間長短不同」。**

例如回測期間設定 2016～2025：

| 股票 | 可取得歷史     |
| -- | --------- |
| A  | 2005～2025 |
| B  | 2012～2025 |
| C  | 2019～2025 |
| D  | 2023～2025 |

這種情況下，我**不建議把短歷史股票排除，也不建議把它上市以前當成 0% 報酬**。

## 我建議用「各股票可觀測期間 + 組合共同期間」兩種結果

### ① 個股層級：只計算實際存在的期間

C 股票只有 2019～2025：

```text
C 的總報酬 = Price(2025) / Price(2019) - 1
```

然後可以計算：

```text
CAGR = (Ending / Beginning)^(1/年數) - 1
```

**不能假設 C 在 2016 年就存在。**

---

## ② 組合層級：從「組合真正成立」開始計算

假設你的 100 支股票全部在 2026 年才確定成為研究池，但你想回測它們過去的總報酬。

這時候其實有兩個不同問題。

### A. 「這100支股票歷史表現如何？」

那麼可以讓每支股票從自己的上市日開始。

例如：

```text
A ───────────────────────── 2025
B       ─────────────────── 2025
C              ──────────── 2025
D                     ───── 2025
```

但是此時**不能直接把100支股票的 CAGR 算術平均**。

應該先建立 Portfolio NAV。

---

# 最推薦：Daily Portfolio NAV

假設100支股票等權：

```text
每支股票初始權重 = 1%
```

某天只有90支有歷史資料，這裡有兩種定義。

### 方法 1：固定權重

例如：

```text
A 1%
B 1%
...
C 1%
D 1%
```

如果 D 尚未有資料：

```text
D = 0%
```

其實這會導致前期只有部分資產被投入。

所以這種方法**不適合拿來代表100支股票的完整投資組合報酬**。

---

# 方法 2：每日重新正規化

我更推薦這個。

假設某一天：

```text
100支股票
↓
90支有價格資料
↓
10支尚無資料
```

把原本的 1% 權重：

```text
90 × 1% = 90%
```

重新 normalize：

```text
每支 = 1% / 90% = 1.1111%
```

因此：

```text
Portfolio Return
=
Σ(可觀測股票權重 × 個股當日報酬)
```

最後每天累積：

```text
NAV_t = NAV_(t-1) × (1 + Portfolio Return_t)
```

---

# 但是，我會再加一個非常重要的限制

如果你的目的只是：

> **比較這一籃子股票的歷史總報酬能力**

那麼最好不要讓「只有上市兩年的股票」和「上市20年的股票」完全公平地競爭。

例如：

| 股票 |  歷史 |
| -- | --: |
| A  | 15年 |
| B  | 14年 |
| C  | 12年 |
| D  |  2年 |

D 剛好在 AI 行情最強的兩年上市：

> +300%

如果你直接納入，可能會嚴重拉高整個籃子的歷史績效。

這不是 Survivorship Bias，而是：

> **不同 Observation Window / 不同樣本期間造成的比較偏差。**

---

# 因此我建議你的回測工具提供 3 種模式

## Mode A — Full Available History

每支股票：

> 從它有資料的第一天開始。

用途：

**了解每支股票自己的完整歷史表現。**

---

## Mode B — Common Period

例如全部股票共同都有資料的期間：

```text
最晚上市股票 = 2019
↓
統一從 2019 開始
↓
所有股票一起比較
```

用途：

**最公平的橫向比較。**

這是我認為你要比較「一籃子股票總報酬率」時，最重要的一個結果。

---

## Mode C — Portfolio Dynamic Entry

這個比較接近真實投資：

```text
股票 A
從 2016 開始

股票 B
從 2018 開始

股票 C
從 2020 開始
```

股票出現後才加入 Portfolio。

這回答：

> **如果這一籃子股票逐步進入市場，我的組合實際會得到多少報酬？**

---

# 我會特別避免一件事

不要這樣：

```text
A CAGR = 15%
B CAGR = 12%
C CAGR = 30%
D CAGR = 50%

Portfolio CAGR
= (15 + 12 + 30 + 50) / 4
= 26.75%
```

**這是錯誤的。**

因為 CAGR 不是可直接加權平均的日／年報酬。

應該：

```text
個股價格
↓
個股報酬
↓
Portfolio Daily Return
↓
Portfolio NAV
↓
Total Return
↓
CAGR
```

---

# 對你目前的研究，我最建議的報表

你的大量股票回測程式最後不要只輸出一個 CAGR。

應該同時輸出：

| 指標                           | 意義           |
| ---------------------------- | ------------ |
| Full-history individual CAGR | 每支股票自己的 CAGR |
| Common-period CAGR           | 公平共同期間 CAGR  |
| Dynamic-entry Portfolio CAGR | 動態加入的組合 CAGR |
| Total Return                 | 真正累積總報酬      |
| MDD                          | 最大回撤         |
| Sharpe                       | 風險調整報酬       |
| Number of stocks             | 每期實際股票數      |
| Average history length       | 平均歷史資料長度     |
| Min history length           | 最短歷史長度       |
| Median history length        | 中位數歷史長度      |

這樣就能清楚知道：

> **高報酬到底是因為股票本身真的強，還是因為某些股票只有很短、但剛好非常漂亮的歷史期間。**

### 所以針對你剛才澄清的情況，我會修正前面的建議：

**不需要 Cash substitution，也不需要把「未上市」當成問題。**

你真正需要處理的是：

> **「不同股票的歷史樣本長度不同」**

而最好的解法是 **Full History + Common Period + Dynamic Entry 三種結果並列**。

如果是要做一個嚴謹的「大量股票組合總報酬回測工具」，我會把 **Common Period 作為主要公平比較結果，Dynamic Entry 作為實際投資情境，Full History 作為個股診斷結果。**
